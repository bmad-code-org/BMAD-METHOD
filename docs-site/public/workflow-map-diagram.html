BMad Method Workflow Map

Use the planning the work needs, then build one change at a time.

1. Define intent

Use a brief, PRD, UX design, architecture, or spec when the work needs shared decisions. A standalone story or bug can go directly to Build.

2. Plan and track

bmad-preview-ticketing slices initiatives into epics and epics into ordered tickets.toml entries. No story file is required to build an entry.

3. Build

bmad-build builds the selected entry or direct intent. Explicitly dispatch each unattended ticket to bmad-build-auto. The joined plan records the baseline and stops at built.

4. Review and decide

bmad-code-review appends findings to the plan without changing status. The user or orchestrator marks work done. Keep completed plans as live state.

5. Finish the epic

bmad-retrospective reads preserved evidence and writes epic-<slug>-retrospective.md directly in the epic. Ticketing handles confirmed closure.

When plans change

bmad-correct-course assesses user-described affected work and proposes document edits and a ticketing handoff.
