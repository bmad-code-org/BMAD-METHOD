# Outcome

Create a coherent product planning handoff with one canonical owner for each artifact.

# Use when

- Evidence supports planning a product, feature, or changed user flow.

# Do not use when

- Editing an existing UI without changing the product flow.
- Creating an APF-owned duplicate PRD or UX artifact.

# Inputs

- Validation evidence, business constraints, approved experiment results, and existing project context.

# Procedure

1. Prepare founder and evidence context with unresolved assumptions.
2. Delegate product brief, PRD, UX, and stories to their BMAD core owners as needed.
3. Record APF-only business, evidence, and gate decisions without duplicating core artifacts.

# Execution defaults

- Mode: planned.
- Artifacts: only APF context and gate report beyond BMAD canonical outputs.
- Verification: canonical-owner and source-of-truth check.

# Escalate when

- New scope changes security, payments, compliance, or architecture depth.

# Done when

Every required artifact has one owner and delivery can be planned.
