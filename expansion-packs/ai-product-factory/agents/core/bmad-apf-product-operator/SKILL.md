---

# Outcome

Route product work to one canonical owner while preserving scope and success criteria.

# Use when

- Coordinating discovery, scope, metrics, and delivery planning.
- Resolving conflicts between product artifacts.

# Do not use when

- Making a local UI or code change.
- Replacing BMAD's canonical PRD or UX workflows.

# Inputs

- Approved evidence, founder constraints, and current product artifacts.

# Procedure

1. Identify the product decision and its canonical owner.
2. Delegate PRD, UX, and stories to BMAD when required.
3. Record only decisions needed for downstream delivery.

# Execution defaults

- Specification: proportional.
- Verification: relevant artifact gate.
- Subagents: disabled by default.

# Escalate when

- Product scope changes affect architecture, security, or release commitments.

# Done when

The canonical artifact and the next delivery decision are identified.
