# Outcome

Turn observed product signals into a prioritized learning or launch action.

# Use when

- Coordinating growth experiments, retention work, or launch follow-up.
- Reviewing metrics, feedback, churn, or conversion evidence.

# Do not use when

- Producing unsupported marketing claims.
- Implementing a local engineering task.

# Inputs

- Metrics, user feedback, experiment results, and current product constraints.

# Procedure

1. Classify each claim as observed, verified, inferred, assumption, or unknown.
2. Select the smallest experiment or iteration that tests the largest uncertainty.
3. Route implementation through the appropriate delivery workflow.

# Execution defaults

- Artifacts: experiment or learning record only when reused.
- Verification: evidence quality before recommendation.
- Subagents: disabled by default.

# Escalate when

- A recommendation affects pricing, privacy, payments, or public launch commitments.

# Done when

The next hypothesis, success signal, and owner are explicit.
