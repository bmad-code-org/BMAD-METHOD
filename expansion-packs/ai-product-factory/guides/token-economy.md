# Экономия токенов и лимитов

Skills не экономят лимит сами по себе: расход определяют прочитанный контекст, число модельных циклов, артефакты, subagents и проверки. В APF используйте наименьший безопасный процесс.

| Задача | Запуск | Что будет отключено по умолчанию |
| --- | --- | --- |
| Текст, CSS, маленький UI-fix | `bmad-apf-execute` → `patch` | spec, артефакты, subagents, полный тестовый набор |
| Локальная feature или refactor | `bmad-apf-execute` → `focused` | spec-файл, subagents, полный тестовый набор |
| Несколько модулей, API, migration | `bmad-apf-execute` → `planned` | всё лишнее; допускается один компактный план и релевантные проверки |
| Auth, payments, sensitive data, destructive migration | `bmad-apf-execute` → `critical` | экономия вторична: нужны план, security-проверки и полный релевантный набор тестов |

Для совсем очевидного локального изменения обычный prompt в Codex с актуальным `AGENTS.md` будет дешевле любого router. Для командной работы `bmad-apf-execute` полезен, когда надо автоматически применить правила проекта и не дать задаче незаметно вырасти в тяжёлый pipeline.

Практика:

- Не запускайте `bmad-help`, lifecycle workflow или нескольких агентов для одной понятной правки.
- Явно укажите `mode=patch`, `tests=off` или `subagents=off`, если риск это позволяет.
- Читайте только ближайший `AGENTS.md` и нужный reference; не загружайте весь `docs/ai/`.
- Для проверки используйте smallest useful command и компактный вывод.
- Повышайте режим только при риске, а не из-за длины prompt.

`bmad-apf-project-contract create` дороже обычной задачи, но запускается один раз на проект и затем уменьшает повторное исследование репозитория всей командой.

> Текущий benchmark проверяет корректность выбора режима, а не реальные credits или токены. Численный процент экономии нужно подтверждать телеметрией Codex на задачах вашего проекта.
