`bmad-project-context`를 사용해 모든 AI 에이전트 세션에 코드에서 유추할 수 없는 최소한의 검증된 지식을 제공하세요. 항상 불러오는 작은 커널과 지식 번들은 새 프로젝트와 기존 코드베이스 모두에 적용됩니다. BMad 설치 여부와 관계없이 작동합니다.

:::note[필수 조건]

- BMad Method가 설치된 저장소와 아무것도 설치되지 않은 저장소를 모두 지원합니다. 이 스킬은 처음 실행할 때 자체 유틸리티 스크립트를 준비해 독립적으로 작동합니다.
  :::

## 사용 시점

- 기존 코드베이스에서 AI 지원 작업을 시작할 때(기존 프로젝트의 진입점)
- 새 프로젝트에서 구현 전에 기술 스택, 규칙, 제약 조건을 기록하고 싶을 때
- 에이전트가 프로젝트와 맞지 않는 결정을 반복할 때
- 컨텍스트가 오래됐거나 불필요하게 커졌다고 느낄 때(Audit 실행)

## 1단계: 실행하기

```bash
bmad-project-context
```

"프로젝트 컨텍스트 설정", "컨텍스트 새로 고침", "컨텍스트 감사"처럼 원하는 작업을 일반 문장으로 말하면 스킬이 적절한 의도로 안내합니다. 기본값은 Ingest입니다. 처음 실행할 때는 컨텍스트가 저장될 위치(`project_knowledge` 폴더)와 에이전트가 컨텍스트를 불러올 방식을 확인합니다. BMad 커스터마이징 배열, `AGENTS.md`의 관리형 블록 또는 둘 다를 선택하세요.

## 2단계: 코드가 알 수 없는 내용만 답하기

기존 코드베이스에서는 스킬이 먼저 코드, 설정, 계획 문서, 문서 폴더를 조사합니다. 질문은 짧게 나눠서 합니다. 먼저 증거와 함께 추론한 내용을 확인하므로 몇 초 안에 답할 수 있습니다. 그다음 위험 요소, 수정하면 안 되는 영역, 조직 요구 사항처럼 실제로 알아낼 수 없는 내용만 묻습니다. 코드로 답할 수 있는 질문은 하지 않습니다. 조직 핸드북, 위키 내보내기, MCP 지식 베이스처럼 저장소 밖에서 가져올 자료도 같은 방식으로 조사합니다. 사용할 수 있는 자료를 물을 때 알려 주세요.

## 3단계: 만들어진 내용 검토하기

결과로 지침 예산을 넘지 않는 커널(`kernel.md`)과 작은 항목으로 구성된 번들을 얻습니다. 각 항목은 사용자가 확인한 `verified` 또는 추론했지만 확인되지 않은 `generated`로 표시됩니다. `index.md`는 스크립트가 생성합니다. 코드가 이미 말해 주는 내용은 설명하지 않습니다. 그런 항목이 있다면 Audit이 삭제합니다.

시간이 지나도 정확하게 유지하려면 다음 기능을 사용하세요.

- **Refresh** — 실제 변경이 생긴 뒤 실행합니다. 지난 실행과의 차이만 확인하며 이미 정한 내용을 다시 묻지 않습니다.
- **Audit** — 필요할 때 실행합니다. 오래된 정보 점검, 경로 확인, 가지치기 테스트를 수행하며 전체 크기는 그대로 유지되거나 줄어듭니다.
- **Query** — 다른 스킬이나 사용자가 번들에 있는 내용을 질문하면 신뢰 메타데이터와 함께 답합니다.

## 폐기된 이전 스킬

:::note[bmad-generate-project-context 또는 bmad-document-project를 찾고 있나요?]
두 스킬 모두 폐기되었으며 이제 이 스킬로 연결됩니다. 기존 트리거 문구는 계속 작동합니다. 기존 `project-context.md`도 하위 호환성을 위해 계속 불러옵니다. 다음 Ingest 때는 조사 원본으로 사용합니다.
:::
