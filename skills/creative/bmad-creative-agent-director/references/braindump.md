# Braindump capture

The outcome is a verbatim corpus file at `{record_folder}/braindumps/YYYY-MM-DD-<slug>.md` holding the creator's raw ideas in their own spoken or written phrasing. Polishing destroys the raw material that `WEAVE` lifts from, so every fragment, slang phrase, and natural cadence marker stays untouched.

## What you cannot infer

- Before creating the file, confirm `{record_folder}/README.md` exists; if not, copy `assets/record-README.md` to `{record_folder}/README.md`.
- If the user brings an existing voice memo transcript, rambling note, or interview file, file the untouched original into `{record_folder}/braindumps/YYYY-MM-DD-<slug>.md` with frontmatter naming the topic, medium, audience, and source date, then organize extracted beats underneath `## Raw excerpts` without rewriting the words.
- Otherwise run a live one-question interview. Ask one focused question per turn and stop once ideas repeat or the user calls it.
- Follow the creator first: when an answer lights up on a story, a scene, or a phrase they clearly enjoy, ask about that next. Between threads, cover whichever of these angles are still thin, in any order:
  1. Core claim or story premise they genuinely believe.
  2. Who it is for and what shifts in them afterward.
  3. Concrete story or case they would tell a friend across a table.
  4. Strongest objection a skeptic would raise and how they answer it.
  5. What everyone else gets wrong about this topic.
  6. Observable proof, example, or scene that makes the claim real.
  7. One-breath payoff and what the audience should feel or do.
  8. Ask verbatim or clearly: *"What should they actually see — a scene, diagram, comparison, prop, or graphic moment?"*
- Append answers directly to `{record_folder}/braindumps/YYYY-MM-DD-<slug>.md` under question headings as each turn arrives rather than reconstructing from memory later.

## Hand back

The braindump file path, the sharpest live quotes captured, any thin topics left open, and an offer to proceed into `WEAVE`.
