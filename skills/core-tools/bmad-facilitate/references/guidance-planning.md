# Planning guidance

For plans, requirements and cases for a decision. These rules add to the skill's; the template's own comments win over them.

## Opening

When the document plans work the ticket tree will hold, an initiative is active or a ticket is in play, and neither the caller nor the ticket gives the altitude, the first opening question asks which level of the tree the document is for: the program, the initiative or one of its epics. The answer sets what the document decides. A template's second opening question then waits for the read-back.

## Stakes

Read the stakes as one of: hobby or personal use, internal, pitch or investor, publication, public launch, regulated or contracted.

- At hobby stakes, one line fills a section. Skip reconciliation unless the user wants it, and run no reviewers and no `skill:` doc standard.
- Below regulated or contracted stakes, default and tag. At them, ask instead, and invent no regulation, citation or threshold. An obligation the user did not name, from you or a reviewer, is an open question; headless, so is anything you would have asked.
- Only at launch, regulated or contracted stakes may a review fix make the document longer.

## Ids and requirements

Give stable ids to anything others will cite, each a short uppercase prefix, a hyphen and a number, such as `FR-3`, the form the id check reads. Where the document carries requirements or scope, make each requirement testable and each edge explicit; coaching a requirements document stops when the remaining questions reach edge cases and trade-offs. Names, owners and dates in the body come from the user, never the environment.

## The level below

A document over its template's length pushes detail down to the level below or splits. A review finding that would grow the agreed scope, or add detail the level below should decide, is no fix here: send it to that level or the open questions unless the user asks for it by name. Defer each open item with an owner and a revisit condition.
