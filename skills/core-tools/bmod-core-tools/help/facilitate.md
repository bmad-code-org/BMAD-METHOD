# Facilitated documents from templates

Open this when the user asks what `bmad-facilitate` can write, how to call it without an agent, or how a team adds its own document templates.

## What it is for

It coaches the user through one document from a template, and later updates or validates it. Any document works, software or not. The user supplies what only they know; the skill reads their inputs, finds facts, reviews the draft and polishes it. Rigor follows the stakes where the template names them; the shipped templates run from a hobby project to regulated or contracted work. A PRD goes to John (`bmad-agent-pm`); a product brief, PRFAQ, business case or BRD to Mary (`bmad-agent-analyst`); a founder's business document to Nadia (`bmad-founder-agent-advisor`).

- How a run opens is the template's call: its `opening` says what to ask or ask for first, and the skill invites the user to say everything at once unless the template rules that out. A PRD asks whether the product is new; a postmortem asks for the records before anyone speaks from memory; a startup diagnostic starts cold with one hard question at a time. A template with no `opening` gets only the invitation. After a brain dump comes "anything else?", then a read-back. Unless the run is fast, the questions whose answers change several sections come next, before the first section. There is no fixed number of questions per message: related ones are grouped, unrelated ones wait.
- A run is in one of three modes. Step-by-step, the default, takes one section at a time in order. Freeform works the sections in any order and grouping that fits, each shown to the user before the review; John's launch plan starts that way. Fast drafts first and then walks the guesses. A template's `mode` sets where its runs start; a team or one person sets `mode` once through `bmad-customize`, which then wins over every template's; the user can switch for one run by asking.
- A template with `order: fixed` runs a request for freeform step-by-step, and fast keeps its order, because its order is the point; each section's comment sets the voice and stance for that part. Shipped: Mary's PRFAQ and opportunity, John's pitch, the experiment card they both offer, Method's postmortem, and Nadia's co-founder agreement, startup diagnostic, positioning, first hire and validation experiment.
- Each message that asks something opens with a progress line, such as `PRFAQ · Customer FAQ (2 of 4)` or `PRD · 3 of 8 done`, counted against the template's facilitation order.
- Every section is settled before the end, in every mode: required ones filled, optional ones offered, include-when ones checked against their condition. Asking for fast never drops a section quietly.
- Fast folds the opening into one batch: what the template requires, topped up with a few high-impact questions. It drafts the rest with each guess tagged `[ASSUMPTION]` in the document, then offers to walk the user through those.
- It skips questions only when the user says headless or autonomous, or hands over material and asks for the document. It then fills gaps with best guesses, tagged as assumptions.
- Documents show what has a shape as a table, a Mermaid diagram, a drawn SVG or a generated image where the host can make one, in place of the paragraph it would take; a template can name the picture a section carries or ban pictures. The team's `visuals` setting changes the default.
- John's PRD comes at two levels. `prd`, for work with several capabilities, is thin and has no requirement lists: after the brain dump John proposes the epics, the work's cohesive capabilities, and from then on a detail that belongs to one epic is saved under it. Its `OKRs` grade each key result in three bands, Passable, Good and Excellent, each with how production measures it; John asks what the user wants proven, then proposes the bands for them to react to. Its `Invariants` (`INV-N`) are pass or fail. `prd-epic`, for one capability, is written when that epic's turn comes: it reads the parent PRD, asks only what the epic adds, and distils numbered requirements (`E02-FR-07`) from the journeys and rules. When only one capability comes out of the brain dump, John offers `prd-epic`.
- Unfinished runs resume in a new chat from the document itself. A finished run leaves the document, its companions and its view; working files go to the system temp folder and are deleted at Close, which checks installed modules through `bmad` for what comes next and reminds the user to start a fresh chat or compact.
- With no fitting template it builds a structure for the document type, says so, and at close offers to make it a template.
- Asked to make a template for a kind of document, it coaches the user through one with its own `document-template` template, which holds the rules for a good template, and writes the file to `_bmad/custom/facilitate-templates/` unless told otherwise.

## Templates the modules ship

Core tools ships only the template for writing templates. Each module's templates are in `templates` in `knowledge.py`'s output once it is installed, so recommend a module when the user wants one it holds:

| id | Module | Recommend when |
|---|---|---|
| `decision-record` | Method | Any decision worth recording: context, options, choice, consequences. |
| `postmortem` | Method | Something went wrong and the team needs causes and actions, blamelessly. The timeline is drawn as a diagram, and it also writes a customer notice when customers were told. |
| `security-review` | Method | Reviewing a system against the OWASP Top 10 or STRIDE. The standard's items drive the questions; another standard needs its rows added to the catalog first. |
| `proposal` | Founder, through Nadia | Asking for money, time or approval: a grant, a bid, an internal request. The reader's own guidelines replace its headings. |
| `pitch-deck` | Founder, through Nadia | A talk or pitch that needs a story and slides. It always renders as an HTML slide view unless the team's or user's `view` setting says otherwise. |
| `character` | Creative Intelligence Suite 0.4.0 and later | A fictional character for a story, game or campaign. The coach proposes options, and each character gets its own one-page HTML sheet unless the team's or user's `view` setting says otherwise. |

Method also ships John's planning templates and Mary's analysis templates, which Method's own help covers. Founder ships fifteen more business templates, which Nadia offers and Founder's own help covers.

## Listing what it can coach

When the user asks what it can coach them through or which templates exist, list them instead of answering from this file, because `templates` in `knowledge.py`'s output covers only what installed modules ship, and a team's own templates appear nowhere else.

1. Run `uv run "{project-root}/_bmad/scripts/list_templates.py" --libraries-of "<bmad-facilitate's folder>" --libraries-of "<each installed agent whose customize.toml sets template_libraries>" "<bmad-facilitate's folder>/assets" --project-root "{project-root}" --root "<folder>"`, with one `--root` for each skills folder the host has active, project folders first. `bmad-ingest`'s library holds another kind of template, so leave it out.
2. Group `templates` by `source`, saying what each is for and naming its `extensions`. Name anything `shadowed`, `orphaned` or `unreachable`, and follow any `tool_sources`. The two default folders showing as `missing` is normal.

## Calling it directly

The user says what they want in plain words: the topic, a template (an id, a file path or a URL), an output folder, the stakes, and whether to run without questions. For example: "bmad-facilitate coach me through a security review covering the OWASP Top 10, output to docs/owasp". It infers what is missing. "Update" or "validate" with a document's path revises it or reviews it without changes. A document written without a template works too: it finds the closest template and uses that as the bar, then offers suggestions or a reshape.

## A team's own templates

Who does what: `bmad-facilitate` writes every new template; `bmad-customize` changes a template that exists or a setting, and hands a new document type to `bmad-facilitate`; Smithy (`bmad-toolsmith`) decides when an agent should carry templates, has the engine write them, and wires the agent to them. Templates are files in `_bmad/custom/facilitate-templates/`, and settings go in `_bmad/custom/bmad-facilitate.toml`, both committed so everyone gets them.

- Add a template: ask `bmad-facilitate` to make one, or write a file in that folder with `template` and `description` in its frontmatter, and any rubric beside it. `facilitation_order` lists the sections by id (the heading lowercased, punctuation dropped, spaces as hyphens) in the order they come up; a section is required unless its comment starts `optional` or `include when`; `list_templates.py` reports ids and headings that do not match.
- Template extensions & checks: `guidance` points to a relative file of family rules (such as `guidance-method.md` in Method or `guidance-planning.md` in Founder). `companions: [...]` tracks expected sibling files beside the document; `forbid_id_prefixes: [...]` disallows leaking id prefixes in `check_doc.py`; `lint:` names a relative script or command to run at Finalize (such as Method's `check_ids.py` for ID-heavy templates). A plain markdown file of headings works too; a bare `## Table of Contents` heading after the title makes the skill fill and check one.
- Replace or edit a shipped template: copy it from `doc-templates/` in the record of the module that ships it into that folder and keep its `template` id. The project's copy wins.
- A module adds templates through `doc-templates/` in its record folder; no setting is needed. An `agents:` frontmatter list names the skills that run one, so help can say who offers it.
- Keep personal templates for every project in `~/.bmad/facilitate-templates/`. The project's folder is searched first.
- Use a shared library: add a folder or a pinned GitHub URL to `template_libraries`, in the `.user.toml` when it is private. Only sources the team controls, because a template overrides the skill.
- Add to a template without copying it: a file with `extends: <id>` in its frontmatter, holding the extra sections and comments. It applies on every run of that template, and updates to the original still arrive. Each section it adds goes where its comment says, even first under the title, and is required unless the comment says optional or include when. It can also set the template's `layout` and `view`, so `extends: prd` with `view: always` makes HTML for every PRD. A section with a template section's heading replaces it or adds to it, as its comment says, and an extension's `facilitation_order` that leaves a template section out removes it. Each run merges the template and its extensions into one file, so recommend an extension over a copy unless the user wants to rebuild the template. For example, an `extends: proposal` file at Fernhollow Bank, a fictional company, adds a required Approval Track with three fixed choices and an empty Review Comments section.
- An organization can keep templates and extensions in its own modules, one per program if it likes, such as `bmod-fernhollow-cards`. A module adds new ids or extends existing ones; only a project's folder or a library replaces an id.
- In `bmad-facilitate.toml`, `visuals` is one sentence on how far documents go in pictures, `style` sets the design guide for HTML artifacts (a CSS file, design-system doc, reference HTML/screenshot, or verbal preferences), and `view` is `offer`, `always` or `never` for every document (`never` disables HTML output globally; `always` builds it by default). `style` and `view` win over a template's own, and a template's comments win over `visuals`; left empty, a template's `view` or `style` holds, else `offer` and creative domain-tailored styling. At close, HTML artifacts are composed creatively around `{doc}` with full fidelity (and offered in native host artifact surfaces when available), steered by any `layout` comment or reference file supplying ideas or fixed brand elements — never rigid value injection. The coaching stays in the markdown template.

The file format and worked examples are at `https://docs.bmad-method.org/customize/write-a-document-template/`.
